## 阶段 D：EasyEDA 适配器（`.eprj3` 本地文件解析）

**接入点**（已有干净缝隙，不用新 port）：`app/sourceExtraction.ts` 是唯一分派点。

1. `packages/shared/src/circuit/ir.ts`：`circuitSourceKindSchema` 加 `"easyeda_sch"`（+ `"easyeda_pcb"`）。
2. `app/sourceExtraction.ts:detectCircuitSourceKind` 加 `.esch2` → `easyeda_sch`、`.epcb2` → `easyeda_pcb`；`extractCircuitSource` 加对应 `case`。
3. 新 domain 解析器（全纯函数、零 IO，与 `kicad*` 同构）：
   - `domain/easyedaLog.ts`：V3 日志解码——按行切分，每行 `outer||inner|` 两个 JSON；`DOCHEAD` 划文档边界；**按 `type`+`id` 取最大 `ticket`（同票比小 `client`）做日志合并**；`inner = ""` 或 `isDelete` 视为删除。
   - `domain/easyedaSchematic.ts`：`parseEasyedaSchematic(text)` → 器件（`COMPONENT` + 按 `parentId` 关联的 `ATTR`：`Designator`/`Value`/`Device`/`Footprint`）、引脚（`PIN` + 必需的 `NAME`/`NUMBER` ATTR）、导线（`WIRE`/`BUS` 的 `dots` + `NET` ATTR）。（PCB 版本用显式 `PAD_NET`。）
   - `domain/easyedaConnectivity.ts`：由导线几何 + 引脚坐标 + 网络名推导连通性（对应现有 `kicadConnectivity.ts`）——**这是本阶段主要工作量**。
   - `domain/easyedaDesign.ts` → `elementsFromEasyedaSchematic(...)` 进 `irBuild.ts`。
   - `domain/easyedaLayout.ts`：产出面板渲染用的 layout（对应 `kicadLayout.ts`）。
4. 元素 id 约定：器件 `easyeda:<记录 id>`（文件内唯一、跨重解析稳定）、引脚用 `NUMBER`、网络复用 `makeNetId`/`pickNetName`/`synthesizeNetName`（`circuitNaming.ts` 保留部分）。irId 走 `circuitIrIdOf`（确定性、编辑后不变），`sourceWatcher` 自动获得 stale 能力。
5. UI：`circuitPanelSource.ts` 的扩展名映射与 `previewPaneContent.tsx` 加 `.esch2`/`.epcb2`。

**P1 边界（写进 CONTRACT.md，不静默猜）**：只支持 V3 `.eprj3` 的 `.esch2`/`.epcb2` 单页文件；旧版 `.eprj`/`.eprj2`（二进制/SQLite）不支持；不做多页/层次网络的跨页合并；不复刻 EasyEDA 的封装库解析。

**测试**：`test/circuit/easyedaLog.test.ts`（DOCHEAD 分界、ticket 合并、删除）、`easyedaSchematic.test.ts`、`easyedaConnectivity.test.ts`、`easyedaIr.test.ts`（id 跨重解析稳定 + 修正能重新套用）；手写最小 `.esch2` fixture（照 AGENTS.md §10.1：不用真实客户设计）。`shared/test` 补 source kind 用例；`circuit-plugin` 工具表更新为 6 个。E2E：`packages/desktop/test/e2e/circuit-panel.test.ts` 加一条「打开 `.esch2` fixture → 面板渲染」。

**spec 先行**：`docs/circuit/README.md` §1 把「立创 EDA」从 P2 提到 P1、更新 P1 输入列与分期表；§3.1 表格；§4 加新 source kind；§8 文件树入口；两份 `CONTRACT.md` 加 EasyEDA 解析器契约与边界。
