# SVN 需求设计

## 文档定位

这份文档描述 SVN 支持第一期的产品需求基线：范围、语义、用户场景与验收标准。底层 service、RPC 与 svn CLI 细节见 [architecture.md](./architecture.md)，界面与交互见 [ui.md](./ui.md)。

## 背景

大量用户项目使用 SVN 工作副本。当前 ESCode 只支持 Git（见 `docs/git/`），在 SVN 工作副本中打开 workspace 时，改动审阅、提交、历史等能力全部不可用，Agent 也无法感知版本控制上下文。

## 产品原则

1. **按 SVN 原生语义呈现，不模拟 Git。** SVN 是集中式版本控制，没有本地提交、暂存区和推送。界面与文案使用 SVN 术语，不出现“推送”“拉取”“暂存”。
2. **Git 链路不受影响。** SVN 是并列能力，现有 Git 行为、接口与测试保持不变。
3. **状态以工作副本为准。** 界面只镜像 `svn` 命令返回的结果，不做乐观修改。
4. **凭据交给 svn 自身管理。** ESCode 不持久化 SVN 密码。

## 术语映射

| 用户意图            | Git 中的对应         | SVN 第一期                     | 界面术语（zh / en）  |
| ------------------- | -------------------- | ------------------------------ | -------------------- |
| 把改动写入仓库      | commit + push        | `svn commit`，直接写入服务器   | 提交 / Commit        |
| 获取他人改动        | pull                 | `svn update`                   | 更新 / Update        |
| 丢弃本地改动        | discard              | `svn revert`                   | 还原 / Revert        |
| 切换分支            | switch               | `svn switch ^/branches/<name>` | 切换 / Switch        |
| 解决冲突            | —（Git 未实现）      | `svn resolve`                  | 标记已解决 / Resolve |
| 清理中断残留锁      | —                    | `svn cleanup`                  | 清理 / Cleanup       |
| 暂存 / stash / 推送 | stage / stash / push | 不提供                         | —                    |

## 范围

### 第一期包含

- VCS 类型检测（`none | git | svn`）与 workspace 级手动覆盖
- 会话状态面板环境区的 SVN 入口与改动统计（位置同 Git）
- 变更列表（含未纳入版本控制、冲突分组）与 inline diff
- 勾选文件提交，支持 AI 生成提交信息
- 更新（update）与远端新修订提示
- 还原（revert）
- 文件级冲突处理：用我的、用他们的、手动编辑后标记已解决；树冲突只读展示
- 单线历史列表（工作副本根 URL），支持按作者 / 关键词筛选已加载范围，查看修订详情与 diff
- 单文件历史与 Blame：从改动行查看该文件的历史，以及逐行的修订号 / 作者
- 分支显示与切换（`svn switch`）
- 分支合并（`svn merge`）：把 trunk / 其他分支的改动合并到当前工作副本，冲突复用现有冲突处理
- 工作副本锁定提示与用户触发的清理
- 认证失败时的凭据弹窗
- 文件树 SVN 状态标记与忽略文件置灰
- 会话状态面板的改动摘要；Review 中的“上一轮更改”来源继续可用
- Agent 感知：system prompt 注入 SVN 快照；bash 策略识别 svn 只读子命令
- 运行环境：Desktop、Web、远程 workspace（SSH / WSL / Docker）、Rust Host；Windows / macOS / Linux

### 第一期不包含（第二期按顺序推进）

1. 分支拓扑图谱（copyfrom 与 mergeinfo）
2. externals、lock、shelve

### 明确不做

- 按 hunk 部分提交、SVN changelist
- 三方合并编辑器
- 打包分发 svn 二进制
- 自动执行 `svn cleanup` 或超时重试掩盖锁冲突
- 与 Agent bash 中 svn 命令的跨进程锁协调

## 环境要求

- svn 客户端 **1.8 及以上**，由用户自行安装；在 workspace 所在机器（本地或远程 Host）上查找。
- 查找顺序：设置中手动指定的路径 → 环境变量 `ESCODE_SVN_BINARY` → `PATH` 中的 `svn` → Windows 下 TortoiseSVN 默认安装目录（`%ProgramFiles%\TortoiseSVN\bin\svn.exe`）。手动指定的路径优先，便于用户覆盖错误的自动检测结果。
- 找不到或版本过低时，SVN 面板显示安装指引：Windows 提示安装 TortoiseSVN 时勾选 “command line client tools”，或安装 SlikSVN；macOS 提示 `brew install subversion`；Linux 提示使用发行版包管理器。

## VCS 检测规则

1. 从 workspace 根目录向上，分别查找最近的 Git 仓库根与 SVN 工作副本根。
2. 两者都没有：`none`。
3. 只有一种：取该类型。
4. 两者都有：取离 workspace 根目录更近（路径更深）的那个；同一层级时优先 Git。
5. 用户可在 workspace 设置中把 VCS 类型覆盖为 `auto | git | svn | none`，按 workspace 身份 key（`workspaceIdentity?.trim() || workspacePath`）持久化。覆盖为 `svn` 但目录不是 SVN 工作副本时，按“非工作副本”展示，不回退到 Git。

## 核心用户场景与验收标准

### 场景 1：我在 SVN 工作副本里，想知道改了什么

- 会话状态面板的环境区显示 SVN 改动行，存在本地改动时显示 `+/-` 汇总；点击打开审阅面板（内容为 SVN 面板）。
- 打开 SVN 面板后按分组列出：冲突、已修改 / 新增 / 删除、未纳入版本控制。
- 展开文件即可看到 inline diff；二进制文件显示“二进制文件已更改”。
- 在工作区修改文件后，列表在防抖时间内自动刷新，无需手动操作。
- 文件树中对应文件显示 M / A / D / C / ? 等状态标记，`svn:ignore` 命中的文件置灰。

### 场景 2：我想提交部分文件

- 每个文件前有勾选框，默认勾选全部已纳入版本控制的改动，不勾选未纳入版本控制的文件。
- 勾选未纳入版本控制的文件后提交，该文件先执行 `svn add`，再随本次提交一起写入。
- 提交信息可手动填写，或点击生成；生成只参考已勾选的文件。
- 提交成功后显示新修订号，列表刷新，已提交文件消失。
- 提交因“工作副本过期”（out of date）失败时，提示先更新，并提供“更新”按钮。

### 场景 3：我想获取他人的改动

- 点击“更新”执行 `svn update`，完成后显示更新到的修订号与变更文件数。
- 远端有新修订时，SVN 面板标题下显示“服务器有新修订 r{n} · 更新”（低频检查，可在设置中关闭），点击即更新。
- 更新产生冲突时，冲突分组置顶并展开，状态面板改动行显示冲突数。

### 场景 4：更新后出现冲突

- 文本冲突文件提供三个动作：用我的（`mine-full`）、用他们的（`theirs-full`）、打开文件手动编辑。
- 手动编辑后点击“标记已解决”（`--accept=working`）。
- 存在未解决冲突时，提交按钮禁用并说明原因。
- 树冲突与属性冲突只读展示原因说明，并提示在命令行处理；不提供解决按钮。

### 场景 5：我想看提交历史

- 历史弹窗按修订号倒序展示工作副本根 URL 的历史，每页 100 条，可继续加载。
- 每行展示修订号、作者、时间与提交信息首行。
- 可在已加载范围内按作者或关键词筛选。
- 选中修订显示完整提交信息、变更文件列表（含操作类型 A/M/D/R）与每个文件的 diff。
- 已加载过的修订再次打开时直接命中缓存。

### 场景 6：我想切换到另一个分支

- 分支入口（状态面板与输入区）显示当前分支：标准布局显示 `trunk`、`branches/<name>`、`tags/<name>` 中的名字；非标准布局显示相对仓库根的路径。
- 分支列表来自 `^/branches`；非标准布局时提供手动输入相对路径。
- 存在本地改动时切换前确认，说明 SVN 会带着改动切换，可能产生冲突。
- 切换完成后列表与历史基于新 URL 刷新。

### 场景 7：工作副本被锁定

- 任一 svn 命令返回 `E155004`（working copy locked）时，面板顶部显示“工作副本被锁定”提示和“清理”按钮。
- 点击后执行 `svn cleanup`，成功后自动刷新；失败时展示 svn 原始错误。
- 不自动清理，不自动重试。

### 场景 8：服务器要求认证

- 命令返回认证失败时弹出凭据对话框（用户名、密码、“让 svn 记住凭据”）。
- 提交凭据后用该凭据重试原命令**一次**；仍失败则展示错误，不循环弹窗。
- 用户取消时原操作以“已取消”结束。

### 场景 9：Agent 在 SVN 项目中工作

- Agent 的 system prompt 包含：是否 SVN 工作副本、仓库 URL、当前修订号、`svn status`（截断 2000 字符）、最近 5 条日志。
- 收集快照不访问远端或带严格超时，不拖慢会话启动；失败时省略对应字段。
- bash 中 `svn status | info | log | diff | cat | list` 视为只读；`commit | update | revert | merge | switch | resolve | cleanup | add | delete | move | copy | propset` 等需要审批。

### 场景 10：环境不满足

- 未找到 svn 或版本低于 1.8：面板显示安装指引，不显示其他操作。
- Rust Host（`ESCODE_RUST_HOST=1`）与 TS Host 使用同一套 `svn` 服务语义；只有连接到未实现 `svn` channel 的旧 Host 时，面板才显示“当前 Host 暂不支持 SVN”。
- 远程 workspace 的远端机器未安装 svn：同样显示安装指引，指引对应远端系统。

### 场景 11：我想把其他分支的改动合并进来

- SVN 面板顶部提供“合并”入口；工作副本根不是分支根时入口禁用，并说明原因。
- 弹窗列出源分支（标准布局取 trunk 与 `^/branches` 下的分支，排除当前分支）；非标准布局提供手动输入相对仓库根的路径。
- 默认合并源分支的全部可用修订（依赖 svn mergeinfo，已合并过的修订不会重复应用）；可勾选“指定修订范围”填写起止修订号。
- 合并是写操作：执行 `svn merge --accept postpone`，完成后面板自动刷新；不自动提交。
- 合并产生冲突时冲突分组置顶展开，提交按钮禁用，走场景 4 的冲突处理流程。
- 成功后 toast 显示合并的文件数与冲突数；工作副本根不是分支根、修订范围非法、目标不合法时以 `invalid-request` 结束。
- 认证失败与非交互命令语义与更新、切换一致（凭据弹窗重试一次）。

### 场景 12：我想看某个文件的历史与逐行归属

- 每个已纳入版本控制的改动行提供“文件历史”和“Blame”入口；未纳入版本控制的行不提供，目录不提供 Blame。
- 文件历史复用历史弹窗：按修订号倒序展示该文件所在 URL 的历史，分页 100 条；筛选、修订详情与文件 diff 行为与工作副本历史一致。
- Blame 打开独立弹窗：按行展示修订号、作者与内容；文件超过 5000 行时截断并提示。
- 缺失 / 已删除的文件仍可查看历史；Blame 对磁盘上不存在的文件不可用。
- 读取失败（非工作副本、认证失败、二进制文件等）展示 svn 错误；认证失败走凭据弹窗重试一次。

## 非功能要求

- **性能**：变更列表只依赖本地 `svn status`，不加 `-u`；历史分页加载，已加载修订按 `(仓库 URL, 修订号)` 缓存。远端新修订检查默认 5 分钟一次，可关闭。
- **编码**：非 ASCII 路径与提交信息在三平台正确显示与提交。
- **安全**：密码不写日志、不落盘；svn ≥ 1.10 使用 `--password-from-stdin`。
- **国际化**：所有新增文案提供中英文。
- **主题**：遵守 `DESIGN.md`，双主题可用。

## 测试与验收

- 服务层：用 `svnadmin create` 与 `file://` URL 在临时目录搭仓库，覆盖 status、diff、commit（含自动 add）、update、文本冲突与解决、switch、merge（含冲突与修订范围）、单文件历史、Blame、锁冲突与 cleanup、log 分页。
- Rust Host：与 TS 服务在同一份仓库夹具上逐步差分（读面、提交、更新冲突与解决、切换、清理），归一化根路径与提交时间后全等。
- 机器上没有 svn 时测试显式 skip 并输出原因；CI 需安装 svn。
- UI：变更分组、勾选默认值、提交按钮禁用条件、分支名推导、术语文案。
- E2E 至少覆盖：
  1. 修改文件 → 勾选 → 提交
  2. 更新产生冲突 → 解决 → 提交
  3. 切换分支
  4. 合并分支改动 → 冲突或成功 → 提交
  5. 打开文件历史与 Blame → 断言修订 / 行归属
- Agent：SVN 快照收集与截断；bash 策略对 svn 子命令的分类（TS 与 Rust CLI 各自覆盖）。
