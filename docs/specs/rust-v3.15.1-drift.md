# Rust runtime 对 v3.15.1 的重新对齐

2026-10-11。分支在 `872ad96` 之上自带一份与 main 内容相同的 v3.14.3（`328c1a0`，仅 `package.json` 版本号不同），因此以 main 的 v3.14.3（`29628c9`）为三方合并基线，只合入 v3.14.3 → v3.15.1 的增量（`aac4755`，CLI 源码 721 个文件）。桌面默认 runtime 是 Rust，本文逐项判断 Rust 是否跟进、怎样跟进；「已对齐」项都有以 TS 为 oracle 的差分语料或单测。

先例：`rust-v3.14.3-drift.md`。

## 合并时对 Node runtime 的处理

本分支此前把若干 Node 逻辑抽成共享模块供 Rust 工作流宿主复用，上游改的恰是这些逻辑。合并把上游改动移植进共享模块，Node 行为与上游一致：

| 共享模块                                                  | 移植的上游改动                                                                                                                                        |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dynamic-workflow-run-settings-apply.ts`                  | 默认并发语义（`defaultConcurrency` 取代 `concurrencyCeiling`，线上键 `ceiling` 装默认并发）、重跑时按目录重新绑定脚本点名的模型（`bindScriptModels`） |
| `dynamic-workflow-saved-launch.ts`                        | 脚本点名模型的绑定与 `modelBindings` 提交；工作流宿主的 `run.startSaved` 接收 Rust 递来的模型目录                                                     |
| `dynamic-workflow-run-progress.ts`                        | 进度通知保持纯构造，留白（hole）通知照 Node 顺序在其后异步发出                                                                                        |
| `dynamic-workflow-run-hole-notification.ts`               | 新增 `buildWorkflowHoleNotification` 纯构造（Node 行为不变），供工作流宿主复用                                                                        |
| `background-tasks.ts::formatWorkflowTaskNotificationText` | `reportCount`（只带前 256 条 report 时的真实总数）                                                                                                    |

工具面激活（`activateDynamicWorkflowTools`）属于 Node runtime 状态，留在 Node 的薄壳里。

## 不跟进 / 缺口（已知影响）

| 项                                                              | 原因                                                                                   | Rust 当前行为                                                                         |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 插件 UI 面板（MCP Apps，`mcp/readResource` 与 17 个 `mcp/ui*`） | 需要整套沙箱桥接（实例、采样、App 工具认领、资源订阅），规模与 Rust MCP 客户端改造相当 | `plugins/listUiSurfaces` 如实回空列表，不暴露打不开的入口；`mcp/ui*` method-not-found |
| 话题附件下载                                                    | 依赖 Agent→Host 的 `topic/resource/*` 往返与按消息绑定的授权                           | topic 附件回错误                                                                      |
| 话题归档读取                                                    | Rust 未持久化 `botGroupSource` 话题快照                                                | topic 策略回 not_found                                                                |
| 子代理运行时配置（`subagents/readRuntimeConfig`）               | Agent→Host 方向，Rust 子代理配置仍按自身注册表                                         | 不发送该请求                                                                          |
| 记忆 Dream / Semantic Recall                                    | 上游默认检索分支关闭 semantic recall；Dream 为后台整理                                 | 未实现，默认路径不受影响                                                              |
| 官方 Coding Plan 网关、业务 token 缓存等供应商专属请求改动      | Rust 模型层按 Host 每请求下发的凭据工作                                                | 未逐项比对，需在请求头差分用例里复核                                                  |
| AmendWorkflow / FillWorkflowHole 的「本会话 run 免确认」        | Rust 权限判定尚无 `predecessor` / `hole` 回填事实（v3.14.3 起即如此）                  | 照常询问（更保守）                                                                    |
| Agent 描述里的 CreateWorkflow 行                                | Rust 模板按 `dynamicWorkflowEnabled=false` 生成（既有差异）                            | 不含该行                                                                              |

## App 差分用例的夹具调整

- `zcode-cli-rust-differential`：Rust 侧与 Node 使用同一官方插件根目录（`ZCODE_OFFICIAL_PLUGINS_BASE_DIR` 指向 CLI 产物目录）。v3.15.1 起官方插件自带子代理，夹具不对齐会把插件可见性差异误判为运行时差异；新数据目录首次 seed 在 debug 构建上约 5 秒，请求超时相应放宽。
- `fork-child` / `selection-side-session` / `shell-resume-notice`：Rust 侧同样指向 CLI 产物目录的官方插件根（原因同上）。
- `attachment-media`：Anthropic 合并相邻 user 消息后，开头可能有多条 `<system-reminder>`（上下文提醒 + 子代理目录），断言改为跳过全部前导提醒。
- `tool-parity`：TS schema 表补 `FillWorkflowHole` 与 `ReplyToChannel`（后者取 core handler 的 `inputSchema`）。
- `resume-differential`：v3.15.1 起 Node 把同一次提交的多条增量归到同一个 seq，`coversRange` 改为「每个 seq 至少一条增量」；Rust 仍逐条分配 seq，对 reducer 等价（「base 快照 + 续传增量 = 新快照」用例两侧都通过）。
- `session-resume`：Node 的快照消息含 synthetic / model-only 的 `agent_listing_delta` 提醒（App 不显示），Rust 快照按行投影不含 model-only 提醒；只比对 UI 可见消息。
- `node-repl`：v3.15.1 起两侧都在轮尾对 node_repl 用过的 browser 发 `turnEnded`（异步），关闭前等它到达。
- `zcode-cli-rust-prompt` / `zcode-cli-rust-subagents`：断言改为 v3.15.1 语义（目录提醒位于上下文前缀与输入之间；profile 名出现在目录提醒而非 Agent 描述；只统计真实用户输入），并把 sqlite 关闭移入 finally，避免 Windows 上 EBUSY 掩盖真实断言。
